# Template workspace

Lean full-stack starter, pruned from `new-crm-back` and `new-crm-front`.

| Folder | What | Stack |
|---|---|---|
| `template-back` | API | NestJS 11, Fastify, TypeORM, Postgres, 4-layer hexagonal |
| `template-front` | Web app | React 19, Vite, TanStack Query, Zustand, Tailwind 4 |

## Model
- **Auth:** email + password. Register, verify the email by SMTP link, then log in. Cookies hold the tokens.
- **Roles:** two fixed roles. `SUPERADMIN` comes from env. `SPARTAN` is every other user.
- **Approval:** with `REQUIRE_APPROVAL=true` the superadmin approves a verified spartan before first login.
- **Projects:** flat list. Only the superadmin creates, edits or deletes projects. Spartans work inside them.
- **Reference slices:** `project` and `example-item` (back), `projects` and `example-items` (front).
- **Ids and database:** every id is a UUIDv7 generated by PostgreSQL 18. The schema changes only through SQL migrations, applied automatically at boot (no TypeORM synchronize).
- **Background jobs:** work that is slow or touches the outside world runs as a job in a separate worker process. The work itself is done by **engines** (`template-back/src/engines/<id>/`: audit, keyword, content), each written by its own developer who changes nothing outside that folder. See `template-back/src/engines/CLAUDE.md`.

## Start a new project
1. Copy this folder to the new location and rename `template-back`, `template-front`, `app_db`.
2. Back: copy `.env.development.default` to `.env.development`, set secrets and `SUPERADMIN_*`, run `docker compose up -d` (PostgreSQL 18), then `npm run start:dev` (the API) and, in a second terminal, `npm run worker:dev` (runs the jobs). The first boot creates the tables.
3. Front: copy `.env.example` to `.env.development`, then `npm run dev`.
4. Read each app's `CLAUDE.md` before adding features.

## Hand an engine to a developer
1. In `.github/CODEOWNERS` and `.github/workflows/ci.yml` replace the `YOUR-ORG` / `REPLACE-*` placeholders with real GitHub teams and logins, and in GitHub turn on branch protection for `main` ("Require review from Code Owners" + the CI checks).
2. Give the developer their engine folder name (`audit`, `keyword` or `content`) and point them at `template-back/src/engines/CLAUDE.md`. They work on a branch and change only `src/engines/<their engine>/`; CI rejects anything else from them.
3. To add a fourth engine, copy `template-back/src/engines/_template` and have the core team list it in `src/engines/index.ts`.
4. Production only runs the engines named in `ENGINES_ENABLED`, so merged code stays off until the core team switches it on.
